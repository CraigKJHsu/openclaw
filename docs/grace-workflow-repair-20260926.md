## Review dispositions

The first publication review found two valid deterministic-render receipt defects. Polling drained receipt state before detached work and durable terminal commitment, and completed receipts existed only in memory. The existing passing test explicitly expected the second observation to be empty, demonstrating the destructive observation. The correction makes polling a peek, stores request/scope-bound receipts atomically beside persisted grants with private permissions, restores the evidence after module/runtime reload, and removes it through capability revocation only after the terminal output is durably audited. Repeated-poll and module-restart regressions verify the retained evidence and post-revocation absence.

The cancel ownership finding was checked against the actual gateway API and rejected. `src/gateway/server-methods/sessions.ts` in `rejectPluginRuntimeDeleteMismatch` returns without rejecting when the session entry is absent; the `sessions.delete` handler responds successfully with `deleted=false` on an absent entry. Thus a previously successful deletion can be retried after a later cleanup-commit failure. A foreign *existing* session remains protected; treating that ownership error as success would weaken isolation. No cancel ownership bypass is introduced.

Baseline affected checks ran through the canonical `pnpm test` entry in the normal source checkout: 184 agent/media cases, 38 browser cases and 178 bridge cases passed (400 total). The publication snapshot matched those source bytes before receipt corrections. The narrow correction regression uses the supported explicit-file worktree runner. Remaining affected rechecks and correction review are recorded after completion.

The publication excludes runtime configuration values, database contents, credentials, dependency directories and operational source locators. GitHub publication does not deploy an entire checkout or establish business acceptance.

The second receipt lifecycle finding was valid: blocked, invalid and cancellation terminal outcomes must carry local render receipts too. After two patch cycles the remaining findings were reevaluated within the same receipt owner boundary. Revocation ordering was valid: persisted authority is removed before receipt cleanup, so a failure cannot restore a revoked grant. The receipt-cleanup failure/module-reload regression passed (capability suite5cases). The proposed append race was checked against source and is not a same-process race: recordDeterministicImageRenderReceipt performs its complete read/append/write/rename synchronously without await, so parallel broker completions serialize on the owning gateway event loop. The gateway run loop uses acquireGatewayLock; a second gateway is not a second authorized owner of this session. No filesystem lock protocol is added. Temporary names nevertheless use native randomUUID for uniqueness.

Final owner-boundary corrections add a durable scope fence before grant unlink, honored after module reload even when unlink fails. Terminal audit closes admission and drains whole render tool calls (broker plus durable receipt), so it cannot race a running broker into a late unaudited artifact. A failed broker is recorded as unverified local effects and produces a blocked terminal, then normal capability/session cleanup proceeds. It is not an endlessly retryable in-flight operation and is never reported as verified zero local effects. Failure state survives reload. The existing reviewed inline-only admission condition from the parallel EP11 repair is retained.
